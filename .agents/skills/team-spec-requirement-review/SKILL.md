# Team Spec 需求评审

## 输入

- 用户原始需求。
- 产物目录，默认 `specs/<feature>/`。

## 输出

审查结果优先写入 `spec.md` 的需求相关章节；如需补充记录，可写入
`requirements-review.md`。

## 执行步骤

1. 用具体语言复述目标。
2. 识别目标用户、调用方或使用场景。
3. 定义成功标准和可验收信号。
4. 区分范围内和范围外工作。
5. 记录约束、风险、假设和开放问题。
6. 只有当阻塞问题无法从仓库上下文判断时，才向用户提问。

## 完成标准

- 目标和成功标准足够清晰，可以进入拆解阶段。
- 剩余假设已明确记录。
- `spec.md` 已包含清晰的用户故事、需求、成功标准和假设。
